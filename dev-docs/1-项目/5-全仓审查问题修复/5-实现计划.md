# 全仓审查问题修复实现计划

本计划只编排尚未实施的工作。唯一技术方案是[技术设计](4-技术设计.md)，唯一验收入口是[验收标准](3-验收标准.md)。当前工作树含其他代理未隔离的代码和测试改动；开始任何任务前必须重新记录 SHA、改动所有者和隔离工作树。本文件不授权编码。

## 交付范围

P0 包含：PC 页面 origin、Android 管理二级 Power、Settings draft、Agent revision/ETag/If-Match 与唯一仓储、event v2、cursor v2 严格全序及 v1 回退、Android 文件会话、Launcher 双门禁。P1 包含可访问性、响应式、资源化、设备/桌面和性能证据、历史 UI 台账复验。

当前源码核验显示这些 P0 契约尚未完成：PC `agentApi.ts` 仍从可变 `baseUrl` 取请求地址；Agent 的 `EventEnvelope` 只有 `type/payload/timestamp`，`FileListingEndpoints` 仍是 offset/materialized list，`SettingsEndpoints` 未处理 ETag/If-Match；Android 虽已去除顶级 Power 枚举，但 `MaimaiNavHost` 尚无 Admin→Power route，`AdminViewModel` 直接修改 settings snapshot。不得将工作树中的局部改动作为闭环完成。

## 可并行工作

P0-02 可与 P0-04 并行；P0-01 的 UI 骨架可与 Agent 工作并行，但不得接入未完成的新契约。P0-03、P0-05、P0-06、P0-07 分别依赖 P0-04 或其所需协议。P1 只能在对应 P0 自动化通过后进入人工验收。

## 风险检查

- Agent 配置文件与 Task Scheduler 不提供硬事务；不可证明补偿时必须保留 journal 并阻止继续写入。
- cursor v2 不承诺目录变化时连续分页或精确 total；无索引时每页仍可能扫描目录。
- Android 当前仅构建 `arm64-v8a`；真实设备/AVD和交互式 Windows 桌面尚无通过证据。
- 两个基线失败、未定义的兼容窗口及当前共享工作树均为编码前阻断项。

## 完成门槛

所有 P0 的 TEST/ACC 证据、两个基线复跑、P1 适用人工证据、`docctl validate --root dev-docs`、链接检查和 `git diff --check` 均通过后，才可由发布负责人进行发布判定。任何未执行项标为未执行、环境阻塞或失败，不能折算为通过。
