# 全仓审查问题修复验收标准

本文是本项目唯一的 AC 入口。协议字段、失败语义与实现边界只以[技术设计](4-技术设计.md)为准；本文不把计划中的 TEST-ID 写成已经存在的测试。

## 验收范围

| AC-ID | 可验证标准 | REQ |
|---|---|---|
| AC-01 | 同源部署时 REST/WS/下载均到页面 origin；切换 Agent 后发生导航，旧缓存/socket/延迟响应不能更新新页。 | REQ-01 |
| AC-02 | 设置只改草稿；成功后 UI 与响应 revision/权威快照一致。校验、409、网络、部分失败可见，草稿不丢失且不报成功。 | REQ-02、05、06 |
| AC-03 | Launcher 从 settings 取项目、runtime 取运行态，按设置顺序展示；仅 enabled 项可启动，禁用项零请求；show/start/stop 在允许状态各一次、忙碌不重复，失败保留权威状态并显示稳定错误/恢复反馈。 | REQ-03、06 |
| AC-04 | settings.updated、任一 launcher.* 及其他领域事件只刷新相应查询；每次成功重连、实例变更或 sequence gap 后每个受影响可见领域恰好对账一次；未知事件后有效事件仍工作。 | REQ-04、06 |
| AC-05 | 并发 Settings/FileRoots 后配置可解析，未修改段逐字段保留；陈旧 revision 稳定拒绝。注入持久化/应用/AutoStart 失败时可区分阶段，未确认生效不发成功且可 GET/日志对账。 | REQ-05、06 |
| AC-06 | 有 capability 时使用 cursor，连续页稳定追加、无重复漏项、每 cursor 单在途；无 capability 回退 offset；无 total 不显示精确总数。 | REQ-07 |
| AC-07 | 只读根操作不可触发，删除/覆盖确认前零请求；截断说明已显示/是否更多，仅服务端给 total 时显示；失败不清列表且可重试。 | REQ-08 |
| AC-08 | Android 仅五项底栏；从管理风险操作进入 Power，返回管理；Power 非第六顶级路由。 | REQ-09 |
| AC-09 | 管理校验/服务端错误保留草稿；三种 Launcher 空态的文案/下一步不同；资源编译通过且触及页面未新增直接用户中文。 | REQ-10 |
| AC-10 | 320/768/1024 和键盘下 PC 核心流程无关键不可达；读屏取得 Dialog 角色、标题、说明、标签、错误、按钮，Tab 不入背景，Escape/取消回焦。 | REQ-11 |
| AC-11 | 每个基线有 REQ/AC/处置。命令、ABI、测试数、产物、历史结论均有源码或版本化日志；ABI 不匹配记录设备、ABI、命令、日志、未覆盖范围、解除条件、补测责任。 | REQ-12 |

## 验收条目

1. 每个 P0 项必须保存候选 SHA、命令、退出码、原始输出和对应 TEST/ACC 证据。失败、flaky、未执行或环境阻塞均不通过。
2. AC-06 的无重复/无遗漏仅适用于同一 directory identity/change stamp、root/path/limit/sort 和未过期 cursor 链。`409 directory_changed` 或 `410 cursor_expired` 后必须零 entries 继续拼接，并从首页建立新会话。
3. Android/Windows 人工项必须使用兼容设备或交互式桌面。当前 APK 仅 `arm64-v8a`，x86_64 不能替代该证据。
4. `docctl validate --root dev-docs` 和 `git diff --check` 仅是文档门禁，不替代产品、测试或设备验收。

## 非验收范围

认证、凭据、CORS、LAN 策略、目录索引、事件回放、跨资源硬事务、历史 Round-2 UI 整体返工以及 P5/P8 视觉延期均不属于本次验收对象。
