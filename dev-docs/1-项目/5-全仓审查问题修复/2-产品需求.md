# 全仓审查问题修复：产品需求

> 本文是本项目 REQ、范围和优先级的唯一产品来源；[验收标准](3-验收标准.md)是 AC 的唯一入口，[技术设计](4-技术设计.md)是唯一技术权威，[审查问题处置台账](8-调研/4-审查问题处置台账.md)记录问题事实。历史 Gate 批准不等于本项目已实施或验收。

## 目标与场景

修复当前全仓审查的逻辑、便利性、UI/UX、可访问性、文档和测试治理缺口，并落实已批准的 PC Web 同源导航、Android 五项底栏/管理二级 Power、Agent 完整协议升级和 cursor v2。管理员能跨端管理设置、启动器、文件和 Power；断线后看到 Agent 权威状态；键盘、读屏和窄屏用户能完成核心操作；维护者能核验构建、ABI 和文档。

成功条件：每个当前 P0/P1 基线均可追溯至 REQ/AC、测试或人工证据及文档事实。环境阻塞只能标为阻塞或未执行，不能标为通过。

## 范围、非范围与优先级

**范围：**PC Web 同源导航、状态隔离、设置草稿、启动器、实时对账、响应式和 Dialog；Android 五项底栏、管理 Power 二级、管理表单、启动器、文件反馈和本期资源化；Agent 配置并发/部分失败、条件更新、事件 v2、能力协商、Launcher 契约和 cursor v2；文件保护；审查、测试、ABI 和文档治理追溯。

**非范围：**认证、凭据、加密、LAN/网络边界、权限、渗透测试；iOS、公网控制、遥测、CI/CD、新业务域；未声明目录新建/删除/跨根移动；重写启动器命令或文件路径规则；重开历史 Round-2 UI。I3/I7/I11/I12/I13/I21 只复验 Round-3/4 裁决，P5/P8 保持接受性视觉延期。

| 优先级 | 定义与判定 |
|---|---|
| P0 | 主机/数据一致性、写入完整性、协议兼容、关键启动操作或文件保护；未关闭不得声称核心修复完成。 |
| P1 | 核心任务可达性、可理解性、可验证性或文档治理；发布前验收，延期须书面记录风险、责任人与期限。 |

本期不使用 P2，避免跨工件将同一问题降级。

## 业务规则、边界与失败行为

1. 一次 PC 页面生命周期只服务一个 canonical origin；切换后旧缓存、旧 socket、延迟响应不得写入当前 UI。
2. Launcher 设置顺序即候选展示顺序，运行态不重排；show 不需危险确认；运行、启动、停止中禁止重复动作，运行时只停当前项。
3. 保存失败不清草稿、不显示成功；冲突不得静默覆盖，须重新取得权威状态。
4. capability 缺失时用已批准 v1 行为；未知事件、可选字段或 capability 不崩溃、不掉线。
5. 无效输入零写入、零成功事件；无法确认最终生效即失败或需对账，不得当成功。
6. 同 cursor 至多一个在途；目标、根、路径变化废弃旧响应；加载失败保留列表并允许重试。
7. 未确认删除/覆盖、禁用启动项、离线/陈旧目标均不得发变更请求；错误须说明恢复动作或不可用原因。
8. ABI/设备环境阻塞只能说明未覆盖范围，不能折算为通过。
