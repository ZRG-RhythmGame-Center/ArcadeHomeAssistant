# 全仓审查问题修复 — 测试策略

> 本策略以本轮已批准决定为唯一测试模型：PC Web 只在**当前页面同源**调用相对 HTTP/WS；切换 Agent 使用保留当前路由的整页导航。Android 顶级导航保持五项，Power 是管理页“风险操作”的二级页，系统返回管理页。不得再以跨源请求、六项底栏或其他目标模型设计/判定测试。

## 1. 风险、优先级与退出条件

| 风险 ID | 风险与失败后果 | 优先级 | 最小充分验证 | 退出判据 |
|---|---|---:|---|---|
| RISK-WEB-ORIGIN | 页面 origin、API 或 WS 目标分裂，导致错误 Agent、缓存串数据或跨源请求 | P0 | WEB-01、WEB-02 | 所有 API 为相对 `/api/...`，WS 从当前 `window.location.origin` 推导；切换只发生一次整页导航且保留 route |
| RISK-SETTINGS-CAS | 陈旧写覆盖新设置，或 Settings/FileRoots 并发、外部副作用失败造成半配置 | P0 | WEB-03～05、AGT-01～04 | revision/ETag/If-Match、唯一仓储、412 零副作用、422/503 恢复和事件/快照一致 |
| RISK-EVENT-V2 | v2 逆序、缺号、实例变化或 v1 事件使客户端陈旧/风暴 | P0 | AGT-05、WEB-10～11、AND-03～05 | v2 按 instance+sequence 对账，v1 保守失效；每次恢复对可见域一次 HTTP 对账 |
| RISK-FILES-V1 | 现有 offset 分页在切根、切目录、刷新和双击加载更多时串页 | P0 | AND-06、AGT-06 | v1 以 rootId/path/generation 和单页在途保护；旧响应不能提交，失败保留已加载项 |
| RISK-FILES-V2 | cursor 可伪造、跨 root/path 重放、排序不全序或目录变化后产生重复/遗漏 | P0（能力开启时） | AGT-07～10、AND-07 | cursor opaque；严格全序；同 rootId/path/sort 才可用；非法 400、scope mismatch 400、过期 410；目录变化 409 且重开 session |
| RISK-POWER-NAV | 高危关机从错误入口/目标执行，或返回栈错误 | P0 | AND-01、AND-02 | 仅 Admin 风险操作可进入 Power；返回 Admin；未确认、离线或能力缺失均零 POST |
| RISK-LAUNCHER | 启动项契约与真实命令不一致、重复启动或失败假报成功 | P0 | AGT-11、WEB-07～09 | enabled 项、`itemId`、稳定错误码、一次命令、状态/事件刷新均由契约和隔离 E2E 证明 |
| RISK-USABILITY | 对话框、窄屏、表单失败恢复不可用 | P1 | WEB-12～14、AND-08～10、AVA-01～07 | 语义、焦点、失败恢复和人工证据达到用例预期 |

P0 失败、flaky、未执行或环境阻塞均阻断发布；能力未声明 `fileListingCursor` 时，v2 条件集记为“不适用”，但 v1 必过集仍为 P0。P1 不得在无证据时标通过；P2 仅可由发布负责人书面豁免。

## 2. 分层、测试数据与可重复性

| 层级 | 责任 | 工具/隔离 | 最小充分覆盖 |
|---|---|---|---|
| 单元/组件 | 状态机、URL/导航构造、全序 comparator、cursor 解码、generation、错误映射、Compose route | Vitest、JUnit 5/Coroutines、Compose/Robolectric、xUnit | 所有 P0 正常、边界和失败分支；不以 sleep 观察竞态 |
| HTTP/WS 契约 | Agent 公开 HTTP header/body/status、v1/v2 DTO、事件信封 | ASP.NET TestServer、MockWebServer、真实 WebSocket 测试端 | 不锁错误展示文本、时间戳或临时绝对路径；锁状态码、稳定 error、字段和顺序 |
| 集成/压力 | 仓储串行化、文件系统、恢复日志、目录枚举 | 临时目录、故障注入、固定种子 barrier | 200 混合写与 10 次目录采样；保留 JSON/hash/日志 |
| 浏览器/设备/桌面 E2E | 同源页面、整页导航、真实命令、网络恢复、OS 焦点 | Chromium、arm64 Android 设备或 AVD、交互式 Windows VM | P0 Launcher、Power、重连、文件主路径；Windows UI 不能由 headless 替代 |

| 数据集 | 内容与约束 |
|---|---|
| TD-ORIGIN | origin A 与 origin B 均托管同一静态 bundle；A/B 各有不同 `/api/status` 标识；不得配置 CORS/proxy 来模拟跨源直连 |
| TD-SET | revision `41`/`42` 的完整 settings、可识别 `operationId`、FileRoots 段；每例临时配置文件 |
| TD-EVENT | v1 type-only；v2 同 instance 顺序/重复/逆序/gap；新 instance；ping/pong；断开—重连 |
| TD-FILES-V1 | 两 root、三页 offset 数据、页边界重复项、延迟旧响应、失败重试；每个条目有稳定相对路径 |
| TD-FILES-V2 | 同名大小写、Unicode、目录/文件、cursor 跨 root/path、损坏 token、已失效 token、目录变化前后快照 |
| TD-PERSIST | SettingsMetadata、Launcher、FileRoots、RemoteShutdown；写 temp/replace/runtime apply/补偿/启动恢复故障注入 |
| TD-LAUNCH | 0/1/5 项、disabled 项、busy、404/409/502；仅使用记录调用的无害脚本 |

并发固定随机种子、记录调度顺序；每个临时目录在 finally 清理并断言无 `.tmp`/事务日志残留（故意保留的 partial/recovery 用例除外）。性能预热 3 次、采样 10 次，报告 p50/p95/最大值、设备规格和原始数据。

## 3. 协议与兼容性覆盖矩阵

| 契约 | 必测公开行为 | 用例 |
|---|---|---|
| Settings revision | GET body `revision` 是十进制字符串且 ETag 与之相等；新客户端 PUT 带 quoted `If-Match`；匹配时仅成功一次并 revision +1 | AGT-01、WEB-03～04 |
| 条件失败与旧客户端 | 陈旧 If-Match 得 412 `settings_revision_conflict`、无文件/运行时副作用；迁移期无 If-Match 保持兼容写并带 `Warning: 299`，不能误报 428 | AGT-02、WEB-05 |
| 统一仓储与部分失败 | HTTP、FileRoots、本机 UI/Tray 都经过同一仓储；锁等待超时 409；校验失败零写；补偿成功 503，不能证明完全恢复则 422/503 且保留恢复记录 | AGT-03、AGT-04 |
| 事件 v2 与 v1 | v2 有 `schemaVersion=2`、eventId、agentInstanceId、十进制 sequence、operationId、type、timestamp、payload；v1 可消费但只触发保守失效 | AGT-05、WEB-10、AND-03 |
| cursor v1/v2 | status capability 缺失/false 使用 v1 `rootId/path/offset/limit`；true 才请求 `pagination=cursor` 和 opaque cursor。UI v2 只保存 `nextCursor`，绝不依赖 `loadedOffset` | AND-06、AND-07、AGT-06～10 |
| cursor v2 全序 | 排序唯一为 `kindRank`（目录先）→ `name` OrdinalIgnoreCase → `name` Ordinal；每页拼接后严格递增、每项恰一次 | AGT-07 |
| cursor 安全/一致性 | token 不暴露路径或可编辑 JSON；绑定 rootId/path/limit/sort/目录版本或等价租约；篡改为 400 `invalid_cursor`，scope 不一致为 400 `cursor_scope_mismatch`，过期为 410；目录变化事件/刷新/重连废弃 session 从首页取数 | AGT-08～10、AND-07 |
| Launcher | settings 中 enabled items 为候选；`POST /api/launcher/start` body 只含准确 itemId；show/start/stop 的错误码、事件和 GET 状态可交叉验证 | AGT-11、WEB-07～09 |

## 4. 关键执行顺序和回归选择

1. 先执行 Agent 契约/仓储 P0，再执行 Web、Android 对新能力的条件集；任何 Agent P0 失败不以客户端 mock 代替。
2. Android 文件先跑 **AND-06 v1 必过集**；确认 `/api/status.capabilities.fileListingCursor=true` 后才跑 AND-07 v2 条件集。v2 用例失败不允许通过回填/断言 `loadedOffset` 修绿。
3. Launcher 必须同时满足 AGT-11 契约和 WEB-09 隔离 E2E；二者任一缺失，GATE-LAUNCHER 不通过。
4. 触及 PC Web 时回归 `pnpm --dir apps/pc-web test`、`typecheck`、`lint`、`build`；触及 Android 时回归 debug/release 单测和 JaCoCo；触及 Agent 时全量 `dotnet test`。只在相应目录运行 Gradle Wrapper。

## 5. 性能与残余风险

| 指标 | 负载 | 发布阈值 |
|---|---|---|
| v2 首页/后续页 | TD-LARGE、`limit=100`、本地 SSD | 首页 p95 ≤ 1.5 s；后续页 p95 ≤ 800 ms；最大 ≤ 2.5 s |
| cursor 内存 | 10k 与 50k 条目、相同 limit | 额外峰值随 limit 而非目录总数增长；记录进程内存，超过 150 MiB 阻断 |
| 配置并发 | 100 Settings + 100 FileRoots 混合任务 | 每项为成功或分类失败；最终 JSON 可解析；成功域值可解释；无意外临时文件 |
| 重连 | 断网后恢复 | 10 s 内连接恢复；恢复后 5 s 内完成可见域一次权威 GET；活跃 socket 数为 1 |

残余风险：cursor v2 在无索引下仍扫描目录；文件系统与 AutoStart 不构成硬事务；事件不提供回放；Windows 焦点/托盘依赖交互式会话；安全整改不在本期范围。上述风险必须在报告中保留，不能用自动化覆盖率抵消。
