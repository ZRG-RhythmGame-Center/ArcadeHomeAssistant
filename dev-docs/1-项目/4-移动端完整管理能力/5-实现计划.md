# 移动端完整管理能力 — 实现规划

> [!IMPORTANT]
> 2026-07-16 项目准则已确定所有 LAN 功能免登录、密码、控制令牌和 API Key。本文中管理员认证、Authorization、登录 UI、密码修改和控制令牌任务全部取消；执行顺序以[Android功能缺口调研](8-调研/1-Android功能缺口调研.md)为准，先修上传、WebSocket 心跳并移除 Agent/Android 历史鉴权，再接入设置与启动器。

## 目标

本轮实现交付 Android 移动端的完整 Agent 管理能力，对应原始规划的阶段 8、9、10。分为数据层、UI 层、联调三个大阶段，每阶段内部细分为可独立提交的步骤。

## 前置条件

- Agent 侧阶段 1-7 已全部完成
- Agent 暴露的管理接口：`GET/PUT /api/settings`、`GET /api/launcher/status`、`POST /api/launcher/show`、`POST /api/launcher/start`、`POST /api/launcher/stop`
- Agent 侧已按 LAN 免凭据准则移除：`POST /api/admin/session` 路由、`Admin.Password` 配置块、设置/启动器/关机接口的 Bearer 鉴权中间件
- 上传与心跳修复（P0-1、P0-2）已完成

## Phase 0: Agent 侧免凭据改造（前置）

目标：清除阻塞管理面板接入的历史鉴权实现，与 LAN 免凭据准则对齐。

任务：

- [ ] 删除 `POST /api/admin/session` 端点及其路由注册
- [ ] 删除 `appsettings.json` 中的 `Admin` 配置块及对应 `AdminOptions` 类
- [ ] 移除 `/api/settings`、`/api/launcher/*`、`/api/power/shutdown` 的 Authorization 头校验中间件
- [ ] 移除 `RemoteShutdown.ControlToken` 字段及关机令牌校验逻辑
- [ ] 补充 Agent 端集成测试：无 Authorization 头时各接口返回 200/4xx 业务状态而非 401

验收：

- 所有原 Bearer 保护的接口在无 Authorization 头时正常工作。
- Agent 启动日志中不再出现 `Admin` 配置加载记录。
- 原有接口的请求/响应结构保持不变（仅删除鉴权层）。

## Phase 1: 数据层 — 模型与 AgentClient 扩展

目标：让 Android 数据层能够与所有管理 API 通信。

### 1.2 AgentClient 新增管理方法

文件: `app/src/main/kotlin/com/maimai/home/data/AgentClient.kt`

- [ ] `fetchSettings(address)` — GET `/api/settings`
- [ ] `updateSettings(address, request)` — PUT `/api/settings`
- [ ] `fetchLauncherStatus(address)` — GET `/api/launcher/status`
- [ ] `showLauncher(address)` — POST `/api/launcher/show`
- [ ] `startLauncherItem(address, itemId)` — POST `/api/launcher/start`
- [ ] `stopLauncherItem(address)` — POST `/api/launcher/stop`

所有方法不再接收密码参数，不构造 Authorization 头。`400 settings_validation_failed` 展示服务端校验错误文本；`409 launcher_item_already_active` / `launcher_item_not_active` 展示为启动器冲突状态；保留现有 LAN 地址校验、超时和 JSON 解析错误处理方式。

### 1.3 更新 Capabilities 模型

文件: `app/src/main/kotlin/com/maimai/home/data/models/AgentStatus.kt`

- [ ] `Capabilities` 新增 `settingsManagement: Boolean = false`
- [ ] `Capabilities` 新增 `launcher: Boolean = false`

### 1.4 数据层单元测试

## Phase 2: UI 层 — 管理面板

目标：实现完整的管理 UI，用户可以通过手机管理 Agent。

### 2.1 AdminViewModel

文件: `app/src/main/kotlin/com/maimai/home/ui/admin/AdminViewModel.kt`

- [ ] 定义 `AdminUiState`：

```kotlin
data class AdminUiState(
    val address: String,
    val machineName: String,
    // 设置
    val settings: AgentSettingsSnapshot? = null,
    val isLoadingSettings: Boolean = false,
    // 启动器
    val launcherStatus: LauncherStatus? = null,
    val isLauncherActionPending: Boolean = false,
    // 编辑状态
    val editedSettings: AgentSettingsUpdateRequest? = null,
    val isSaving: Boolean = false,
    val saveSuccess: Boolean = false,
    // 错误
    val errorMessage: String? = null,
)
```

- [ ] 实现方法：
  - `loadSettings()` — 拉取 `/api/settings` 和 `/api/launcher/status`
  - `saveSettings(request)` — 调用 `updateSettings`，成功后重新加载
  - `showLauncher()` — 调用 `showLauncher`
  - `startItem(itemId)` — 调用 `startLauncherItem`
  - `stopItem()` — 调用 `stopLauncherItem`
  - `refreshLauncherStatus()` — 刷新启动器状态

- [ ] 订阅 EventStream，监听 `launcher.*` 和 `settings.updated` 事件刷新状态
