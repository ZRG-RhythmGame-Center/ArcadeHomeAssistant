# 安卓端能力对齐与开发规划

> [!IMPORTANT]
> 2026-07-16 项目准则已确定所有 LAN 功能免登录、密码、控制令牌和 API Key。本文中管理员登录、Bearer、密码修改和控制令牌相关方案全部废止，不得据此实现；当前优先级与替代方案以[Android功能缺口调研](8-调研/1-Android功能缺口调研.md)和项目根 `AGENTS.md` 为准。

## 背景

Windows Agent 已在 `/api/status` 中声明完整能力，并暴露管理员鉴权、统一设置、启动器管理、音频、文件、远程关机和实时事件接口。Android app 当前已经完成旧核心能力，但尚未接入 Agent 后续新增的管理能力。

本规划用于明确 Android app 与 Agent 主服务之间的能力差距，并作为后续开发 Admin 管理面板的执行依据。

## 当前结论

Android app 已对齐旧核心能力：设备连接、mDNS 发现、音频控制、文件管理、远程关机和基础 WebSocket 事件。

Android app 主要缺口集中在 Agent 新增的管理能力：管理员登录、统一设置读写、启动器控制、启动项管理、管理相关 capabilities 和管理事件处理。

按 API 端点统计，当前至少有 7 个 Agent 端点未接入 Android：

| API | 用途 | Android 状态 |
|---|---|---|
| `POST /api/admin/session` | 管理员密码验证 | 未接入 |
| `GET /api/settings` | 读取 Agent 全局设置 | 未接入 |
| `PUT /api/settings` | 保存 Agent 全局设置 | 未接入 |
| `GET /api/launcher/status` | 查询启动器状态 | 未接入 |
| `POST /api/launcher/show` | 重新显示启动器 | 未接入 |
| `POST /api/launcher/start` | 启动指定启动项 | 未接入 |
| `POST /api/launcher/stop` | 关闭当前启动项 | 未接入 |

## Agent 能力基线

Agent 当前 `/api/status` 返回的 `capabilities` 包含：

```text
audioVolume
audioMute
audioDeviceSwitch
fileManagement
discoveryBroadcast
remoteShutdown
settingsManagement
launcher
```

Android 当前 `Capabilities` 模型只覆盖：

```text
audioVolume
audioMute
audioDeviceSwitch
fileManagement
discoveryBroadcast
remoteShutdown
```

因此需要补齐：

```text
settingsManagement
launcher
```

## 已对齐能力

| 能力 | Agent API | Android 入口 |
|---|---|---|
| Agent 状态读取 | `GET /api/status` | `AgentClient.fetchStatus()` |
| 音频状态读取 | `GET /api/audio/state` | `AgentClient.fetchAudioState()` |
| 音量设置 | `POST /api/audio/volume` | `AgentClient.setVolume()` |
| 静音设置 | `POST /api/audio/mute` | `AgentClient.setMute()` |
| 音频设备列表 | `GET /api/audio/devices` | `AgentClient.fetchAudioDevices()` |
| 默认设备切换 | `POST /api/audio/default-device` | `AgentClient.switchDevice()` |
| 文件根目录列表 | `GET /api/file-roots` | `AgentClient.fetchFileRoots()` |
| 文件列表 | `GET /api/files` | `AgentClient.fetchFiles()` |
| 文件上传 | `POST /api/files/upload` | `AgentClient.uploadFile()` |
| 文件下载 | `GET /api/files/download` | `AgentClient.downloadFile()` |
| 文件删除 | `DELETE /api/files` | `AgentClient.deleteFile()` |
| 文件重命名 | `POST /api/files/rename` | `AgentClient.renameFile()` |
| 文件移动 | `POST /api/files/move` | `AgentClient.moveFile()` |
| 远程关机状态 | `GET /api/power/shutdown` | `AgentClient.fetchRemoteShutdownStatus()` |
| 执行远程关机 | `POST /api/power/shutdown` | `AgentClient.executeRemoteShutdown()` |
| 实时事件连接 | `/api/events` | `EventStream` |

## 未对齐能力

| 能力块 | 缺失内容 | 影响 |
|---|---|---|
| 管理员认证 | 缺少登录 API、登录状态和密码会话 | 无法进入管理面板 |
| 统一设置 | 缺少 `/api/settings` 读取和保存模型 | 无法通过手机管理 Agent 配置 |
| 启动器控制 | 缺少状态、显示、启动、关闭接口 | 无法远程控制 PC 启动器 |
| 启动项管理 | 缺少启动项列表编辑 UI 和保存逻辑 | 无法新增、修改、删除、启用或排序启动项 |
| 文件根目录配置 | 当前只显示脱敏根目录，不支持编辑真实路径 | 无法通过手机调整 Agent 文件根目录 |
| 远程关机配置 | 当前只能输入控制令牌执行关机，不能修改配置 | 无法启停远程关机或修改控制令牌 |
| 管理员密码修改 | 缺少设置保存中的 `adminPassword` 字段 UI | 无法通过手机修改管理员密码 |
| 管理事件 | 缺少 `settings.updated` 和 `launcher.*` 事件响应 | 管理面板无法自动同步 PC 端状态变化 |

## AgentClient 规划

在 `AgentClient` 新增以下方法：

| 方法 | API | 认证 |
|---|---|---|
| `verifyAdminPassword(address, password)` | `POST /api/admin/session` | 请求体密码 |
| `fetchSettings(address, password)` | `GET /api/settings` | `Authorization: Bearer {password}` |
| `updateSettings(address, password, request)` | `PUT /api/settings` | `Authorization: Bearer {password}` |
| `fetchLauncherStatus(address, password)` | `GET /api/launcher/status` | `Authorization: Bearer {password}` |
| `showLauncher(address, password)` | `POST /api/launcher/show` | `Authorization: Bearer {password}` |
| `startLauncherItem(address, password, itemId)` | `POST /api/launcher/start` | `Authorization: Bearer {password}` |
| `stopLauncherItem(address, password)` | `POST /api/launcher/stop` | `Authorization: Bearer {password}` |

错误处理要求：

- `401 admin_unauthorized` 显示为“管理员密码错误”。
- `400 settings_validation_failed` 展示服务端校验错误文本。
- `409 launcher_item_already_active` 和 `launcher_item_not_active` 展示为启动器冲突状态。
- 保留现有 LAN 地址校验、超时、网络错误和 JSON 解析错误处理方式。

## 事件规划

Android 当前已处理 `audio.*`、`file.*`、`power.shutdown.*`。管理面板需要继续处理：

| 事件 | Android 行为 |
|---|---|
| `settings.updated` | 登录状态下重新加载设置 |
| `launcher.shown` | 刷新启动器状态 |
| `launcher.hidden` | 刷新启动器状态 |
| `launcher.minimized` | 刷新启动器状态 |
| `launcher.item.started` | 刷新启动器状态 |
| `launcher.item.failed` | 刷新启动器状态并展示最近错误 |

| `launcher.item.stop.completed` | 刷新启动器状态 |

## 开发阶段

### Phase 1: 数据层最小闭环

目标：Android 能调用所有管理 API。

任务：

1. `Capabilities` 新增 `settingsManagement` 和 `launcher`。
2. 新增 `LauncherStatus`、`AgentSettingsSnapshot`、`AgentSettingsUpdateRequest` 等模型。
3. `AgentClient` 新增管理员、设置、启动器方法。
4. 补充 `AgentClientAdminTest`、`AgentClientSettingsTest`、`AgentClientLauncherTest`。

验收：

- MockWebServer 测试能验证请求方法、路径、请求体、Authorization 头和响应解析。
- 旧状态解析测试仍能通过，缺少新 capability 字段时默认 `false`。

### Phase 2: 管理入口与登录

目标：用户能进入管理 Tab 并完成密码验证。

任务：

1. 新增 `Admin` Tab。
2. 新增 `AdminTabUnconnected`。
3. 新增 `AdminViewModel` 登录状态。
4. `AdminScreen` 支持未连接、未认证、认证中、认证失败、认证成功状态。

验收：

- 未连接时管理页提示先连接设备。
- 错误密码显示“管理员密码错误”，不清空输入。
- 正确密码进入管理面板并触发设置加载。

### Phase 3: 只读管理面板

目标：登录后能查看 Agent 当前配置和启动器状态。

任务：

1. 登录成功后调用 `GET /api/settings`。
2. 同时调用 `GET /api/launcher/status`。
3. 展示启动器状态、全局设置、启动项、文件根目录、远程关机配置。
4. 订阅 `settings.updated` 和 `launcher.*` 事件，刷新状态。

验收：

- 管理面板能完整显示 Agent 设置快照。
- PC 端修改设置后，Android 管理面板能刷新。
- 启动器显示、隐藏、启动项状态变化后，Android 状态能刷新。

### Phase 4: 启动器控制

目标：手机端能控制 PC 启动器。

任务：

1. 实现“显示启动器”。
2. 根据 enabled 启动项生成“启动”按钮。
3. 实现“关闭当前项”。
4. 处理 404、409、502 等错误反馈。

验收：

- 手机端点击显示后，PC 端启动器窗口出现。
- 手机端能启动指定启动项。
- 手机端能关闭当前运行项。
- 已有启动项运行时再次启动能显示冲突提示。

### Phase 5: 设置编辑与保存

目标：手机端能完整修改 Agent 配置。

任务：

1. 编辑开机自启、启动器自动显示、显示延迟、画布尺寸、壁纸路径。
2. 编辑导航键、确认键、关闭键。
3. 编辑启动项列表。
4. 编辑文件根目录列表。
5. 编辑远程关机配置。
6. 修改管理员密码。
7. 保存时调用 `PUT /api/settings`。

验收：

- 保存成功后重新加载设置。
- 服务端校验错误能完整展示。
- 修改管理员密码后，使用新密码重新验证。
- 所有设置修改不影响现有音频、文件、电源页面。

### Phase 6: 联调与文档

目标：完成端到端验证并沉淀开发文档。

任务：

1. 扩展 `ComposeSmokeTest`，覆盖 Admin Tab 导航。
2. 补充 `AdminViewModelTest` 和必要 UI 测试。
3. 更新 `dev-docs/wiki/development/android-mobile-bootstrap.md`。
4. 手动联调密码验证、设置保存、启动器控制和错误场景。

验收：

- `./gradlew.bat testReleaseUnitTest` 通过。
- `./gradlew.bat jacocoTestReport jacocoVerification` 通过或记录未通过原因。
- 手动验证清单全部通过。

## 验证计划

自动化验证：

```powershell
./gradlew.bat testReleaseUnitTest
./gradlew.bat jacocoTestReport jacocoVerification
```

手动验证：

1. 连接 Agent 后进入管理 Tab。
2. 输入错误密码，确认错误提示。
3. 输入正确密码，确认设置和启动器状态加载。
4. 修改设置并保存，确认 Agent 配置更新。
5. 重新显示启动器，确认 PC 端窗口出现。
6. 启动一个启动项，确认状态变为 running。
7. 关闭当前启动项，确认状态回到 idle。
8. 断开 Agent 网络，确认管理面板错误反馈明确。

## 风险与约束

| 风险 | 处理 |
|---|---|
| 管理员密码不持久化导致频繁登录 | 本阶段接受，每次 app 启动重新验证 |
| 设置表单字段较多，移动端编辑复杂 | 先按分区折叠展示，避免单屏堆叠 |
| 文件根目录真实路径编辑风险高 | 保留服务端校验，客户端只做基础非空校验 |
| 启动器操作存在 PC 端状态竞争 | 以服务端返回状态为准，409 明确提示 |
| WebSocket 断线导致状态滞后 | EventStream 重连后触发全量刷新 |
