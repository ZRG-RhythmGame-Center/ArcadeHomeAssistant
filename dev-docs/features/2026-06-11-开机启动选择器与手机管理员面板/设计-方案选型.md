# 开机启动选择器与手机管理员面板方案选型

> 创建日期: 2026-06-11 15:18
> 最后更新: 2026-06-12 22:28
> 作者: Maimai Dev
> 状态: 草稿

## 关联需求

- [开机启动选择器与手机管理员面板需求](需求.md)

## 选型结论

- Windows 启动选择器使用现有 Windows Agent 进程内的 Windows Forms 全屏窗口实现。
- Windows 本机设置窗口使用同一 Windows Forms UI 技术栈，从托盘右键“设置”入口打开。
- 启动项启动和关闭都使用 .NET `ProcessStartInfo`，通过 `cmd.exe /C` 统一承载任意命令行和终端命令。
- 开机自启继续复用现有 `AutoStartManager` 的 Windows Task Scheduler 方案。
- 配置持久化使用 Windows Agent 配置文件，新增 `Launcher` 与 `Admin` 配置段。
- 管理接口继续使用 Windows Agent 内置 ASP.NET Core Minimal API，并新增统一设置接口。
- Android 管理员面板使用现有 Kotlin + Jetpack Compose 页面体系实现。
- 管理员密码使用请求头传递，服务端按配置文件明文密码校验。
- 启动选择器状态变化通过现有 WebSocket 实时事件总线广播。

## 选型理由

当前 Windows Agent 项目已经是 `net9.0-windows`，并且启用了 `UseWindowsForms`，托盘应用也已经有 Windows Forms 消息循环。因此启动选择器和本机设置窗口继续使用 Windows Forms 可以避免引入 WPF、Avalonia、Electron 或额外前端容器，能直接复用同一进程、同一配置、同一日志和同一生命周期。

现有开机自启已经通过 Windows Task Scheduler 创建用户登录任务，且不需要管理员权限。本功能只需要在 Agent 自启动后决定是否打开启动选择器，不需要替换自启机制。

Android 端已经有稳定的 Compose 页面、ViewModel、`AgentClient`、连接状态和错误模型。管理员面板作为一个新顶层页面或设备页子入口即可接入，不需要创建新的移动端架构。

## Windows Agent 模块划分

新增 `Launcher` 模块，放在 `services/windows-agent/src/MaimaiHomeAgent/Launcher/` 下。

核心对象：

- `LauncherOptions`：映射配置文件中的启动选择器配置。
- `LauncherItemOptions`：表示单个启动项配置。
- `LauncherState`：表示当前启动选择器窗口、运行进程和最近错误状态。
- `ILauncherService`：对 API 和托管服务暴露启动选择器能力。
- `LauncherService`：协调窗口显示、启动项执行、进程结束监听和事件发布。
- `ILauncherWindowHost`：抽象全屏窗口，便于测试时替换。
- `WinFormsLauncherWindowHost`：Windows Forms 全屏窗口实现。
- `LauncherEndpoints`：Minimal API 路由定义。
- `AdminOptions`：管理员密码配置。
- `AdminGuard`：校验管理员密码并统一生成未授权响应。

新增 `Settings` 模块，放在 `services/windows-agent/src/MaimaiHomeAgent/Settings/` 下。

核心对象：

- `AgentSettingsSnapshot`：对外暴露的完整配置视图。
- `AgentSettingsUpdateRequest`：远程或本机保存配置时使用的更新请求。
- `IAgentSettingsService`：读取、校验、保存配置的统一用例接口。
- `AgentSettingsService`：协调配置文件读写、开机自启状态、启动选择器配置和敏感字段处理。
- `SettingsEndpoints`：统一设置接口路由定义。
- `ISettingsWindowHost`：抽象本机设置窗口。
- `WinFormsSettingsWindowHost`：Windows Forms 设置窗口实现。

依赖方向：

- API endpoint 只负责 HTTP 入参、鉴权和调用 `ILauncherService`。
- `LauncherService` 负责用例编排，不直接处理 HTTP 细节。
- `SettingsEndpoints` 和本机设置窗口都调用 `IAgentSettingsService`，不各自实现配置读写逻辑。
- `AgentSettingsService` 持有统一校验规则，避免手机端和本机窗口出现不同保存行为。
- Windows Forms 细节限制在 `WinFormsLauncherWindowHost` 内。
- 设置窗口 UI 细节限制在 `WinFormsSettingsWindowHost` 内。
- 进程启动细节限制在 `LauncherService` 或独立 `ICommandLauncher` 内，避免 UI 窗口直接启动外部命令。

## 配置结构

在 `appsettings.json` 中新增配置段：

```json
{
  "Admin": {
    "Password": "seganmsl"
  },
  "Launcher": {
    "ShowOnAgentStart": false,
    "CanvasWidth": 1080,
    "CanvasHeight": 1920,
    "Items": []
  }
}
```

启动项结构：

```json
{
  "id": "mai",
  "name": "maimai",
  "commandLine": "D:\\Games\\maimai\\start.bat",
  "workingDirectory": "D:\\Games\\maimai",
  "stopCommandLine": "D:\\Games\\maimai\\stop.bat",
  "stopWorkingDirectory": "D:\\Games\\maimai",
  "key": "A",
  "order": 10,
  "enabled": true
}
```

说明：

- `ShowOnAgentStart` 只控制 Agent 启动后是否自动显示启动选择器。
- Windows Agent 开机自启状态仍由 `AutoStartManager` 管理，不直接写入 `Launcher` 配置段。
- `CanvasWidth` 固定默认 `1080`，`CanvasHeight` 固定默认 `1920`，后续可保留为配置项以便调试。
- 管理员密码允许明文配置，初始值为 `seganmsl`。

## 全屏启动选择器

Windows Forms 窗口行为：

- 创建无边框窗口。
- 启动时定位到主显示器或后续配置指定显示器。
- 使用全屏显示，目标布局按 1080x1920 竖屏设计。
- 窗口背景保持简洁，不展示背景图、Logo、时间或网络状态。
- 启动项列表固定布局在下半区域。
- 每个启动项显示名称、备注等信息。
- 窗口激活时捕获全局导航键和确认键。
- 确认键触发当前选中的启动项。

启动项触发行为：

- `LauncherService` 校验启动项仍然启用。
- 使用 `cmd.exe /C {commandLine}` 启动命令。
- 如果配置了 `workingDirectory`，则传给 `ProcessStartInfo.WorkingDirectory`。
- 启动成功后记录当前启动项和启动命令进程。
- 启动选择器窗口最小化并保持 Agent 运行。
- 手机端请求关闭当前启动项时，使用 `cmd.exe /C {stopCommandLine}` 执行关闭命令。
- 全局关闭快捷键默认为 `F12`，由 Windows Agent 托盘消息泵注册；按下后调用当前启动项关闭命令，关闭完成后重新显示启动器。
- 如果配置了 `stopWorkingDirectory`，关闭命令使用该目录；否则复用启动工作目录。
- 关闭命令执行完成后，启动选择器窗口重新显示。
- 手机端调用重新打开接口时，启动选择器窗口重新显示。

关闭行为：

- 不默认直接杀死启动命令进程或其子进程。
- 每个启动项必须配置关闭命令，关闭命令可以是脚本或程序。
- 关闭命令负责清理残留进程、临时文件、外部依赖和自身退出流程。
- 如果关闭命令执行失败，启动选择器保持最小化或显示错误状态，由手机端展示失败原因。

重复触发保护：

- 当已有启动项进程未退出时，不再响应新的启动请求。
- 启动失败时窗口保持显示，并在状态中记录错误。

## 管理 API

新增接口建议：

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| `POST` | `/api/admin/session` | 校验管理员密码 | 无 |
| `GET` | `/api/settings` | 获取完整设置视图 | 管理员 |
| `PUT` | `/api/settings` | 保存完整设置视图 | 管理员 |
| `GET` | `/api/launcher/config` | 获取启动选择器配置 | 管理员 |
| `PUT` | `/api/launcher/config` | 保存启动选择器配置 | 管理员 |
| `GET` | `/api/launcher/status` | 获取启动选择器状态 | 管理员 |
| `POST` | `/api/launcher/show` | 重新打开启动选择器 | 管理员 |
| `GET` | `/api/startup/autostart` | 获取开机自启状态 | 管理员 |
| `PUT` | `/api/startup/autostart` | 启用或关闭开机自启 | 管理员 |

鉴权方式：

- Android 输入密码后先调用 `/api/admin/session` 验证。
- 验证成功后 Android 在当前会话内保存密码或短期管理令牌。
- 后续管理接口通过 `Authorization: Bearer {passwordOrToken}` 传递凭据。
- 服务端当前阶段直接将 Bearer 值与配置文件中的 `Admin:Password` 比较。

统一设置接口：

- `/api/settings` 是手机端管理员面板的主要配置接口。
- 单项接口可以保留给调试或内部调用，但 Android 管理员面板优先通过统一设置接口读写。
- `GET /api/settings` 返回完整配置视图，包括开机自启状态、启动选择器配置、启动项、文件根目录、远程关机配置和其他已纳入远程管理的配置。
- `GET /api/settings` 不返回管理员密码明文，只返回管理员密码是否已配置。
- `PUT /api/settings` 支持修改管理员密码，但请求中密码为空时表示不修改现有密码。
- `PUT /api/settings` 保存前执行统一服务端校验。

错误模型：

- 管理员密码错误返回 `401`。
- 启动项 ID 重复返回 `409`。
- 命令行为空、名称为空、工作目录无效返回 `400`。
- 关闭命令为空、关闭工作目录无效返回 `400`。
- 启动选择器不可用返回 `503`。

## Android 管理员面板

新增 `Admin` 页面或在 `Device` 页面增加管理员入口。实现上优先新增顶层目的地，保持配置能力可发现。

Android 侧新增对象：

- `AdminScreen`：管理员登录和配置页面。
- `AdminViewModel`：管理登录态、配置加载、保存和错误展示。
- `LauncherConfig` / `LauncherItem`：与 Agent API 对齐的数据模型。
- `AgentSettingsSnapshot`：与统一设置接口对齐的数据模型。
- `AdminSession`：当前连接设备下的管理员会话状态。
- `AgentClient` 新增管理员和启动选择器接口。

页面能力：

- 未连接 Agent 时显示不可配置提示。
- 未验证密码时显示密码输入框。
- 验证成功后显示开机自启开关。
- 显示启动选择器自动打开开关。
- 显示启动项列表。
- 通过统一设置接口展示和保存所有可远程管理配置项。
- 支持新增、编辑、删除、启用、禁用启动项。
- 支持配置名称、命令行、工作目录和排序。
- 支持配置关闭命令和关闭工作目录。
- 保存前在 Android 端做必填校验。
- 保存失败时显示服务端错误。
- 提供“重新打开启动选择器”按钮。
- 提供“关闭当前启动项”按钮，调用启动项配置的关闭命令。

## 本机设置窗口

托盘菜单新增“设置”项，点击后打开 `WinFormsSettingsWindowHost`。

窗口能力：

- 展示所有可配置项。
- 支持修改管理员密码。
- 支持修改开机自启状态。
- 支持修改启动选择器自动显示状态。
- 支持编辑启动项列表。
- 支持编辑启动项启动命令和关闭命令。
- 支持编辑文件根目录、远程关机控制令牌等已有 Agent 配置。
- 保存前调用 `IAgentSettingsService` 执行同一套校验。
- 保存成功后提示是否已即时生效。
- 对需要重启 Agent 才能生效的配置显示提示。

设置窗口定位：

- 首版使用表单式窗口，不追求复杂视觉设计。
- 目标是让本机可以完整配置 Agent，避免必须通过手机或手写配置文件管理。
- 后续如果配置项增多，可以再拆分为多 Tab 或分组页面。

## 实时事件

复用现有 `/api/events` WebSocket 事件总线，新增事件类型：

- `launcher.shown`：启动选择器已显示。
- `launcher.minimized`：启动选择器已最小化。
- `launcher.item.started`：启动项命令已启动。
- `launcher.item.exited`：启动项进程已退出。
- `launcher.item.stop.started`：启动项关闭命令已启动。
- `launcher.item.stop.completed`：启动项关闭命令已完成。
- `launcher.item.stop.failed`：启动项关闭命令执行失败。
- `launcher.item.failed`：启动项启动失败。
- `launcher.config.updated`：启动选择器配置已更新。
- `settings.updated`：统一设置已更新。

事件用于 Android 刷新状态，不作为配置保存的唯一依据。

## 测试策略

Windows Agent：

- `LauncherOptions` 反序列化测试。
- 启动项校验测试：名称、命令行、禁用项。
- 管理员密码校验测试。
- `LauncherService` 测试：启动成功、启动失败、已有启动项运行时拒绝重复启动、关闭命令成功、关闭命令失败、关闭完成后请求显示窗口。
- API 测试：未授权、配置读取、配置保存、开机自启读写、重新打开启动选择器。
- 统一设置服务测试：完整配置读取、敏感字段脱敏、密码更新、空密码不覆盖、统一校验失败。
- 设置窗口测试：通过窗口保存时调用 `IAgentSettingsService`，不直接写配置文件。
- 事件测试：启动、退出、配置更新事件发布。

Android：

- `AgentClient` 管理接口、统一设置接口序列化和请求头测试。
- `AdminViewModel` 登录成功、登录失败、加载完整设置、保存完整设置校验测试。
- `AdminScreen` 未连接、未登录、已登录配置表单和错误态测试。

## 风险与处理

- 任意命令行执行风险：仅管理员接口允许保存配置，密码由本机配置文件控制，默认只面向局域网使用。
- 明文密码风险：文档明确为本机配置文件明文策略，不在 Android 或 Web 前端展示密码。
- Windows Forms 与 ASP.NET Core 同进程 UI 线程风险：窗口运行在独立 UI 线程，避免阻塞 Web Host。
- 双配置入口不一致风险：本机设置窗口和远程设置接口必须复用 `IAgentSettingsService`，校验和保存路径保持一致。
- 关闭清理风险：启动选择器不直接杀进程，关闭清理由每个启动项配置的关闭脚本或程序负责，避免残留进程和外部依赖未清理。
- 多显示器风险：首版使用主显示器全屏，后续如需要再增加显示器选择配置。
