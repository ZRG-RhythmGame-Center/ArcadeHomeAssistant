# 远程关机立即执行调整需求

> 创建日期: 2026-06-03 09:50
> 最后更新: 2026-06-03 10:05
> 作者: Maimai Dev
> 状态: 已完成

## 背景

远程关机当前定型为高风险立即执行操作。用户在 PC Web 或 Android 输入控制令牌并二次确认后，Windows Agent 直接调用系统关机命令；服务端、客户端和文档不保留旧排程状态或撤销路径。

## 需求范围

- Windows Agent 远程关机接口在令牌校验和 `{ "confirm": true }` 通过后立即调用系统关机命令。
- PC Web `/power` 页面保留控制令牌输入和二次确认；确认文案必须明确“确认后将立即关机”。
- Android 电源页保留控制令牌输入和二次确认；确认后立即调用远程关机接口。
- 远程关机状态响应只返回 `available`、`state`、`error`。
- 实时事件仅保留关机开始执行和执行失败两类远程关机事件。

## 验收标准

- 输入正确控制令牌并二次确认后，PC Web 和 Android 都只发送 `POST /api/power/shutdown`，请求体为 `{ "confirm": true }`。
- 服务端公开接口只有 `GET /api/power/shutdown` 与 `POST /api/power/shutdown`。
- UI 中只展示控制令牌、目标设备、二次确认和执行结果。
- 状态响应只包含能力、状态和错误信息；执行时间仅存在于实时事件 payload。
- 单元测试覆盖立即执行、令牌传递、确认必填和执行失败路径。

## 实现结果

- Windows Agent：`RemoteShutdownService.ExecuteAsync()` 改为立即发布 `power.shutdown.executing` 并调用 `IRemoteShutdownExecutor.ExecuteShutdownAsync()`。
- PC Web：`powerApi` / `usePower` / `PowerPage` 使用 `executeRemoteShutdown` 和 `useExecuteRemoteShutdown`，状态类型收敛为 `available`、`state`、`error`。
- Android：`AgentClient.executeRemoteShutdown()`、`PowerViewModel.executeShutdown()` 和 `PowerScreen` 改为立即执行，数据模型收敛为 `available`、`state`、`error`。
- Windows Agent 实时事件：`/api/events` 不再透传查询参数，远程关机事件 payload 保留 `state`、`executedAt`、`error`。
- 文档：同步更新 Windows Agent、PC Web、Android 和实时事件 wiki，并删除旧远程关机需求索引。
