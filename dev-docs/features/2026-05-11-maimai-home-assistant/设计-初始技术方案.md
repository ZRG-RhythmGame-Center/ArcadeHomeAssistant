## 推荐方案

采用三端结构：Flutter 手机 App、React + Vite PC 网页、C# Windows Agent。

```text
Phone App  ---- HTTP/WebSocket ----+
                                    |
PC Web     ---- HTTP/WebSocket ----+---- C# Windows Agent ---- Windows Core Audio (COM) / File System
```

## 组成

### Windows Agent

Windows Agent 是核心服务，运行在目标 Windows 电脑上。

职责：

- 提供局域网 HTTP API。
- 提供 WebSocket 状态推送。
- 枚举和切换 Windows 音频输出设备。
- 读取和设置系统音量。
- 管理白名单目标文件夹。
- 托管 PC 网页静态资源。
- 提供配对、令牌和基础安全控制。
- 通过托盘程序提供启停和状态查看入口。

推荐实现：

- .NET 9（LTS 之后切 .NET 10），C# 13。
- ASP.NET Core Minimal API 提供 HTTP 接口。
- ASP.NET Core 内置 WebSocket / SignalR 提供状态推送。
- `NAudio.CoreAudioApi` 或 `AudioSwitcher.AudioApi.CoreAudio` 直接调用 Windows Core Audio 接口，覆盖音量、静音、设备枚举、默认输出设备切换。
- `Microsoft.Extensions.Hosting` 统一管理服务生命周期，便于注册为 Windows Service。
- `H.NotifyIcon`（WinForms 版，`UseWindowsForms=true`）实现系统托盘 UI。
- `Makaretu.Dns.Multicast` 负责发布局域网 mDNS / DNS-SD 服务。
- 使用 `dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true` 打包为单文件 exe，目标机器无需安装 .NET 运行时。

## 音频控制方案

### 方案目标

C# 直接通过 Windows Core Audio COM 接口控制音频，避免依赖外部命令行工具，降低分发复杂度并消除杀毒误报风险。

### NAudio / AudioSwitcher

NAudio 与 AudioSwitcher 都对 `IMMDeviceEnumerator`、`IAudioEndpointVolume`、`IPolicyConfig` 等 COM 接口做了 C# 包装，可以在同一个进程内完成全部音频操作。

职责：

- 枚举所有音频渲染设备（输出设备）及其状态。
- 获取和设置当前默认输出设备（同时设置 Console、Multimedia、Communications 三个角色）。
- 获取和设置主音量。
- 获取和设置静音状态。
- 监听 `IMMNotificationClient`、`IAudioEndpointVolumeCallback`，把设备插拔、默认设备变化、音量变化实时推到 WebSocket。

实现选型建议：

- 默认使用 `AudioSwitcher.AudioApi.CoreAudio`，因为它对默认设备切换和角色处理封装更完整。
- 复杂场景或需要更底层控制时，按需引入 `NAudio.CoreAudioApi`。
- 设备插拔与默认设备变化通知通过 `NAudio.CoreAudioApi` 的 `MMDeviceEnumerator.RegisterEndpointNotificationCallback`（`IMMNotificationClient`）实现，封装为 `NAudioDeviceNotificationSource`（实现 `IAudioDeviceNotificationSource`）；`DeviceChangeNotifier`（`IHostedService`）订阅通知并将设备列表变化广播为 `AudioDeviceChanged` 事件；回调内部通过 `IAudioStaDispatcher`（`AudioStaDispatcher` 实现）将 Core Audio COM 调用派发到专用 STA 线程，避免跨公寓编组开销。
- 不再使用 `SoundVolumeView` 等外部 exe，删除 `tools/` 相关目录。

### Mobile App

手机 App 用于日常控制。

推荐实现：

- Kotlin 2.3.0 + Jetpack Compose，AGP 8.7.3，最小 Android API 24。
- 三标签并列底部导航（Connection / Audio / Files），三个目标互为兄弟。
- `ConnectionHandle`（`address` + `machineName`）通过 `ServiceLocator.connectionHandle`（`StateFlow<ConnectionHandle?>`）跨屏共享连接状态；Audio/Files 标签未连接时渲染空状态。
- 通过 HTTP 调用控制接口。
- 通过 WebSocket 接收状态更新。
- 局域网发现：支持手动输入 IP，后续由 Android NSD 扫描 `_maimai-home._tcp.local` 服务。
### 局域网发现方案

第一版网络发现只解决“让手机找到局域网内有哪些可连接 Agent”，不在同一阶段绑定配对和自动连接。

推荐实现：

- Windows Agent：使用 `Makaretu.Dns.Multicast` 发布 `_maimai-home._tcp.local` 服务。
- Flutter Mobile：使用 `nsd` 搜索 `_maimai-home._tcp` 服务并展示结果列表。
- 发现结果至少包含：实例名、主机名/IP、端口、版本。
- 用户点击发现结果后，先回填到连接页，再复用已有 `/api/status` 测试连接链路。

服务广播约定：

- service type：`_maimai-home._tcp.local`
- port：`8765`
- instance name：默认使用机器名
- TXT records 第一版建议包含：
  - `name=<machine-name>`
  - `version=<agent-version>`
  - `path=/api/status`
  - `proto=http`

边界说明：

- 第一版不做自动配对，不做后台自动连接。
- Android 端优先在真机验证，模拟器不作为 mDNS 能力验收环境。
- 若路由器或系统禁用 multicast，允许继续保留“手动输入 IP”作为兜底路径。

`appsettings.json` 中的 `Discovery` 配置节：

| 键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `Enabled` | bool | `true` | 是否启用 mDNS 广播 |
| `ServiceType` | string | `_maimai-home._tcp` | DNS-SD 服务类型 |
| `InstanceName` | string | 机器名 | mDNS 实例名，空字符串时回退到机器名 |
| `Port` | int | `8765` | 广播端口，须与 Kestrel 监听端口一致 |
| `StatusPath` | string | `/api/status` | TXT record `path` 字段值 |
| `Protocol` | string | `http` | TXT record `proto` 字段值 |
| `Version` | string | `1.0.0.0` | TXT record `version` 字段值 |

`appsettings.json` 中的 `Realtime:Heartbeat` 配置节：

| 键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `PingInterval` | TimeSpan | `00:00:30` | 心跳 ping 间隔 |
| `PongTimeout` | TimeSpan | `00:01:00` | 超过此时长无流量则关闭会话 |

### PC Web

PC 网页用于配置、管理和调试。

推荐实现：

- React + Vite。
- 由 Windows Agent 通过 `app.UseStaticFiles` 托管静态文件。
- 不需要单独部署 Node 服务。
- 主要页面包括设备状态、音频控制、文件夹配置、文件管理、连接授权。

## API 草案

### 设备发现与状态

- `GET /api/status`：获取 Agent 状态、机器名、版本、授权状态。

  响应字段（JSON）：

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | `machineName` | string | Windows 机器名 |
  | `version` | string | Agent 版本号 |
  | `startedAt` | string (ISO 8601) | Agent 启动时间（UTC） |
  | `uptimeSeconds` | number | Agent 已运行秒数 |
  | `capabilities.audioVolume` | bool | 是否支持音量控制 |
  | `capabilities.audioMute` | bool | 是否支持静音控制 |
  | `capabilities.audioDeviceSwitch` | bool | 是否支持默认输出设备切换 |
  | `capabilities.fileManagement` | bool | 是否支持文件管理 |
  | `capabilities.discoveryBroadcast` | bool | 是否正在广播 mDNS 服务 |
  | `baseUrl` | string (optional) | Agent 自报的底座 URL（如 `http://192.168.1.5:8765`）；较旧 Agent 不返回此字段 |
- `GET /api/audio/devices`：获取音频输出设备列表。

  响应字段（JSON 数组，每项）：

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | `id` | string (GUID) | 设备唯一标识 |
  | `name` | string | 设备显示名称 |
  | `isDefault` | bool | 是否为当前默认输出设备 |
  | `state` | string | 设备状态：`active` / `disabled` / `notpresent` / `unplugged` |
- `GET /api/audio/state`：获取当前默认输出设备、音量、静音状态。
- `WS /api/events`：推送音频状态、文件操作结果、连接状态变化。WebSocket 消息为 JSON，envelope 结构：`{ "type": string, "payload": object, "timestamp": string (ISO 8601) }`。

  已实现的事件类型：

  | `type` | `payload` | 触发时机 |
  |---|---|---|
  | `audio.state` | 同 `GET /api/audio/state` 响应体 | 音量或静音状态变化后 |
  | `audio.device.changed` | 同 `GET /api/audio/devices` 响应体（数组） | 设备插拔、默认设备变化 |
  | `file.created` | `{ rootId, path, overwritten }` | 文件上传成功后 |
  | `file.deleted` | `{ rootId, path }` | 文件删除成功后 |
  | `file.renamed` | `{ rootId, path, newPath }` | 文件重命名成功后 |
  | `file.moved` | `{ rootId, path, newPath }` | 文件移动成功后 |
### 音频控制

- `POST /api/audio/default-device`：切换默认音频输出设备。

  请求体：`{ "deviceId": "<GUID string>" }`

  成功响应（200）：返回更新后的设备列表（同 `GET /api/audio/devices` 格式）。

  错误响应：`404 { "error": "device_not_found" }` / `400 { "error": "invalid_device_id" }`
- `POST /api/audio/volume`：设置主音量。
- `POST /api/audio/mute`：设置静音状态。

### 文件管理

- `GET /api/file-roots`：获取已配置的目标文件夹列表。
- `GET /api/files?rootId=&path=&offset=&limit=`：浏览目录。支持分页，`offset` 默认 0，`limit` 默认 200。

  响应字段（JSON）：

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | `entries` | array | 当前页文件/目录条目列表 |
  | `total` | number | 目录下条目总数 |
  | `truncated` | bool | 结果是否被截断（`total > offset + limit`） |
  | `limit` | number | 服务端实际使用的分页限制；旧版 Agent 不返回此字段，客户端默认回退到 200 |
- `POST /api/files/upload`：上传文件。
- `GET /api/files/download?rootId=&path=`：下载文件。
- `POST /api/files/rename`：重命名文件。
- `POST /api/files/move`：移动文件。
- `DELETE /api/files`：删除文件（body 传参，需 `confirm: true`）。

### 配置

- `GET /api/config`：读取配置。
- `PUT /api/config/file-roots`：更新可管理文件夹列表。

## 安全设计

- 所有文件操作必须基于 `rootId`，服务端将 `rootId + relativePath` 解析为真实路径。
- 使用 `Path.GetFullPath` 规范化后再校验真实路径必须以对应根目录前缀开头，防止 `..` 路径穿越。
- 拒绝符号链接、Junction、绝对路径输入；必要时使用 `FileInfo.LinkTarget` 检测软链。
- 首次使用生成配对码，手机输入配对码后获取访问令牌。
- 令牌保存在本机用户目录（`%LOCALAPPDATA%/maimai-home-assistant/`）配置文件中，可在 PC 网页撤销。
- 删除和覆盖操作默认需要前端二次确认。

### 配对与令牌接口（`MaimaiHomeAgent.Security`）

**`IPairingService`**

| 方法 | 签名 | 说明 |
|---|---|---|
| `CreateCode` | `PairingCode CreateCode(IPAddress sourceIp, string deviceLabel, TimeSpan? ttl = null)` | 创建一次性配对码，绑定来源 IP，默认 TTL 120 秒 |
| `ExchangeAsync` | `Task<Result<TokenRecord>> ExchangeAsync(string code, IPAddress sourceIp)` | 用配对码换取长期 token；原子单次消费，成功或失败后该 code 均不再可用 |

**`ITokenStore`**

| 方法 | 签名 | 说明 |
|---|---|---|
| `ListAsync` | `Task<IReadOnlyList<TokenRecord>> ListAsync()` | 列出所有已签发令牌 |
| `AddAsync` | `Task AddAsync(TokenRecord t)` | 持久化新令牌 |
| `RemoveAsync` | `Task<bool> RemoveAsync(string id)` | 按 ID 撤销令牌 |
| `ValidateAsync` | `Task<TokenRecord?> ValidateAsync(string token)` | 按 token 值查找；命中且未过期返回记录，否则 null |

**`TokenRecord`**（`record`，字段均不可变）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Id` | string | 令牌唯一标识 |
| `Token` | string | 令牌值（MVP 阶段明文存盘，后续可换 SHA-256 hash） |
| `DeviceLabel` | string | 设备标签（由客户端在配对时提供） |
- `H.NotifyIcon.Wpf` 等托盘库依赖 WPF，需要 `UseWPF=true`，会绑定 `net9.0-windows`。实际采用的是 `H.NotifyIcon`（WinForms 版），配置 `UseWindowsForms=true`，同样绑定 `net9.0-windows`。
| `ExpiresAt` | DateTimeOffset | 过期时间 |
| `IssuedToIp` | string | 签发时的来源 IP |

**`Result<T>` / `PairingError`**

`Result<T>` 是极简结果类型，`IsSuccess` 为 `false` 时 `Error` 为以下枚举值之一：

| 值 | 含义 |
|---|---|
| `None` | 无错误（成功路径） |
| `CodeNotFound` | 配对码不存在 |
| `Expired` | 配对码已过期 |
| `IpMismatch` | 来源 IP 与配对码绑定 IP 不符 |

## 部署形态

- 开发期：`dotnet watch run` 运行 `services/windows-agent`。
- 发布期：单文件 self-contained exe，约 20-40 MB，双击即用。
- 可选：通过 `Microsoft.Extensions.Hosting.WindowsServices` 注册为 Windows Service 实现开机自启；或托盘程序在登录后启动。
- 配置文件路径：默认 `%LOCALAPPDATA%/maimai-home-assistant/config.json`，开发期可在仓库内放 `config.dev.json`。

## 建议开发顺序

1. 实现 C# Windows Agent 最小 API：状态接口、音量读取、静音状态读取。
2. 接入 NAudio / AudioSwitcher，实现音量设置、静音切换、默认输出设备切换。
3. 实现 PC Web 基础控制页，先用浏览器验证完整链路。
4. 实现文件根目录配置和安全路径校验。
5. 实现文件浏览、上传、下载、删除、重命名。
6. 创建 Flutter App，对接已有 API。
7. 加入局域网发现、配对授权和 WebSocket 状态同步。
8. 加入托盘程序、单文件打包和（可选）Windows Service 注册。
