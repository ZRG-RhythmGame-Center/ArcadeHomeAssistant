## 总体目标

先实现一个可用的局域网 MVP：Windows 电脑运行 C# Agent，手机或 PC 网页通过局域网访问 Agent，完成音频控制和白名单文件夹管理。

## 技术栈

- Windows Agent：.NET 9、C# 13、ASP.NET Core Minimal API。
- 音量、静音、默认设备切换：`AudioSwitcher.AudioApi.CoreAudio`，必要时辅以 `NAudio.CoreAudioApi`。
- 后台与生命周期：`Microsoft.Extensions.Hosting`、`Microsoft.Extensions.Hosting.WindowsServices`（可选）。
- 托盘 UI：`H.NotifyIcon.Wpf` 或 `Hardcodet.NotifyIcon.Wpf`。
- 局域网发现：`Zeroconf` 或 `Makaretu.Dns.Multicast`。
- 打包：`dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true`。
- PC Web：React + Vite。
- Mobile App：Flutter。

## 阶段 1：Windows Agent 基础服务

目标：先让局域网内设备可以访问 Windows Agent。

任务：

- 使用 `dotnet new sln` 与 `dotnet new web` 初始化 `services/windows-agent`。
- 用 ASP.NET Core Minimal API 创建服务入口，启用 Kestrel。
- 提供 `GET /api/status`。
- 支持 `appsettings.json` 配置监听地址和端口，开发阶段默认 `http://0.0.0.0:8765`。
- 接入 `Microsoft.Extensions.Logging`，输出到控制台并落本地日志文件。

验收：

- 在 Windows 电脑运行 Agent 后，同一局域网手机浏览器可访问状态接口。
- 状态接口返回机器名、版本、运行时间、功能可用性。

## 阶段 2：音量和静音控制

目标：通过 API 控制 Windows 主音量。

任务：

- 引入 `AudioSwitcher.AudioApi.CoreAudio`。
- 封装 `IAudioService`，实现读取当前主音量、设置主音量、读取静音状态、设置静音状态。
- 提供音频状态接口和控制接口。
- 处理 COM 线程模型（必要时在 STA 线程或专用 `SynchronizationContext` 中调用）。

API：

- `GET /api/audio/state`
- `POST /api/audio/volume`
- `POST /api/audio/mute`

验收：

- 调用 API 能改变 Windows 系统音量。
- 调用 API 能静音和取消静音。
- Windows 系统音量变化后，状态接口能返回正确值。

## 阶段 3：默认输出设备切换

目标：通过 API 切换 Windows 默认音频输出设备。

任务：

- 使用 `AudioSwitcher.AudioApi.CoreAudio` 的 `CoreAudioController` 枚举设备。
- 实现按设备 ID（`Guid`/`DeviceId`）切换默认输出设备。
- 切换时同时设置 Console、Multimedia、Communications 三种角色。
- 注册 `IMMNotificationClient`，监听设备插拔与默认设备变化事件。

API：

- `GET /api/audio/devices`
- `POST /api/audio/default-device`

验收：

- API 能列出可用输出设备，含设备 ID、名称、状态、是否默认。
- API 能切换到指定输出设备。
- Windows 设置中的默认输出设备同步变化。
- 在 Windows 设置面板手动切换设备，Agent 能监听到事件。

## 阶段 4：PC Web 音频控制页

目标：先用网页验证音频控制全链路。

任务：

- 初始化 `apps/pc-web`（React + Vite + TypeScript）。
- 创建音频设备列表页面。
- 创建音量滑条和静音按钮。
- 创建默认输出设备切换按钮。
- 将构建后的静态文件交给 Windows Agent 通过 `app.UseStaticFiles` 托管，开发期使用 Vite dev server 反代到 Agent。

验收：

- 局域网浏览器打开 PC Web 后可以控制 Windows 音频。
- 切换设备和调节音量后页面状态能刷新。

## 阶段 5：文件夹白名单和安全路径

目标：建立安全的文件管理基础，避免任意磁盘访问。

任务：

- 设计 `appsettings.json` / `config.json` 中的 `FileRoots` 段。
- 支持配置多个文件根目录，每项含 `Id`、`Name`、`Path`、`ReadOnly`。
- 实现 `rootId + relativePath` 到真实路径的解析，使用 `Path.GetFullPath` 规范化。
- 校验解析后的真实路径必须以对应根目录绝对路径作为前缀。
- 阻止 `..`、绝对路径、符号链接（通过 `FileInfo.LinkTarget` / `DirectoryInfo.LinkTarget`）逃逸。

API：

- `GET /api/file-roots`
- `GET /api/config`
- `PUT /api/config/file-roots`

验收：

- API 只能访问配置过的根目录。
- 构造路径穿越请求时服务端拒绝访问。
- 单元测试覆盖典型穿越攻击向量。

## 阶段 6：文件管理能力

目标：完成常用文件操作。

任务：

- 实现目录浏览（`DirectoryInfo.EnumerateFileSystemInfos`）。
- 实现文件上传（基于 `IFormFile`，支持流式写入）。
- 实现文件下载（`PhysicalFile` / `Results.File`）。
- 实现文件删除。
- 实现文件重命名。
- 实现同一根目录内移动文件。
- 对覆盖、删除、移动增加服务端保护规则（默认禁止覆盖、危险扩展名提示等）。

API：

- `GET /api/files`
- `POST /api/files/upload`
- `GET /api/files/download`
- `POST /api/files/rename`
- `POST /api/files/move`
- `DELETE /api/files`

验收：

- PC Web 可以浏览、上传、下载、删除、重命名文件。
- 所有文件操作都不能越过配置根目录。
- 单元/集成测试覆盖每种操作的成功与拒绝路径。

## 阶段 7：手机 App

目标：提供手机端日常控制入口。

任务：

- 初始化 Flutter App。
- 实现 Agent 地址配置。
- 实现连接状态页。
- 实现音频控制页。
- 实现文件根目录列表。
- 实现基础文件浏览和常用文件操作。

验收：

- 手机 App 可以连接 Windows Agent。
- 手机 App 可以调音量、静音、切换输出设备。
- 手机 App 可以管理配置范围内的文件。

## 阶段 8：发现、授权和实时同步

目标：提升实际使用体验和安全性。

任务：

- 使用 `Zeroconf` / `Makaretu.Dns.Multicast` 发布 Agent 的 mDNS 服务（如 `_maimai-home._tcp.local`）。
- 手机 App 自动发现局域网 Agent。
- 增加首次配对码（短期有效，绑定来源 IP）。
- 配对成功后签发本地访问令牌（随机 token），存储在 `%LOCALAPPDATA%/maimai-home-assistant/`；核心接口为 `IPairingService`（创建配对码、换取令牌）和 `ITokenStore`（持久化、校验、撤销）。
- 增加令牌列表与撤销 API。
- 添加 WebSocket（`/api/events`）推送音频状态变化、文件操作结果、设备插拔事件。

验收：

- 手机 App 能发现局域网内的 Agent。
- 未配对设备不能调用控制接口。
- 音频状态变化后前端能自动更新。

## 阶段 9：托盘程序、自启与单文件打包

目标：让 Agent 在 Windows 上稳定常驻并便于分发。

任务：

- 引入 `H.NotifyIcon`（WinForms 版，`UseWindowsForms=true`），提供托盘菜单：状态（禁用项）、开机自启切换、退出。
- 自启动通过 `schtasks.exe /Create /SC ONLOGON /RL LIMITED` 实现用户级任务计划，无需管理员权限；任务名固定为 `MaimaiHomeAgent`；`AutoStartManager` 封装 Enable/Disable/IsEnabled 三个操作，依赖 `IProcessRunner` 抽象以便单元测试。
- `TrayBridge` 监听命名管道 `maimai-home-agent-tray`，接收文本命令（当前仅 `invoke:generate-pairing-code`），作为托盘 UI 的测试缝合点。
- 配置 `dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true`，输出单个 exe。
- 在 README 中说明分发与防火墙放行步骤。

验收：

- 用户双击单文件 exe 即可启动 Agent。
- 托盘菜单能显示状态并切换开机自启（LAN-only 部署，无配对码菜单项）。
- （可选）安装为 Windows Service 后开机自启正常。

## 风险和注意事项

- COM 调用需要正确处理线程模型，长生命周期事件订阅要在 Agent 退出时显式释放，避免泄漏。
- 不同 Windows 版本和声卡驱动可能导致设备名称不稳定，统一以设备 ID 为主键，名称仅展示。
- 单文件 self-contained 发布体积较大（20-40 MB），可在 README 中说明并启用 trimming（确认与 NAudio/AudioSwitcher 的兼容性后再开启）。
- `H.NotifyIcon.Wpf` 等托盘库依赖 WPF，需要 `UseWPF=true`，会绑定 `net9.0-windows`。
- 文件删除和覆盖操作必须谨慎，默认应让前端二次确认。
- Agent 监听 `0.0.0.0` 时必须启用鉴权，避免局域网内其他设备误操作；同时引导用户在 Windows Defender 防火墙放行。
