# Android 端页面分配与操作逻辑优化方案

> 创建日期: 2026-06-01 17:47
> 最后更新: 2026-06-01 17:51
> 作者: Maimai Dev
> 状态: 草稿

## 背景

当前 Android App 使用 Kotlin + Jetpack Compose + Material 3 实现，底部导航包含三个一级页面：

- 连接
- 音频
- 文件

现有结构已经满足 MVP 使用：用户先连接 Windows Agent，再进入音频控制或文件管理。近期在实际设备上检查布局时发现两个体验问题：

1. 顶部区域视觉占用偏高，需要统一 Material 3 顶部栏与页面壳布局。
2. “连接”作为长期常驻一级 Tab 的语义偏窄，无法完整表达已连接设备管理、切换、断开、历史设备等长期任务。

本方案用于指导后续 Android 端 UI 信息架构与操作逻辑调整。

## 目标

1. 将页面分配调整为更符合长期使用场景的 Material Design 主任务结构。
2. 弱化“连接”作为一次性动作的地位，将其升级为“设备”管理页。
3. 在所有主任务页统一展示当前连接设备上下文，降低误操作风险。
4. 保持音频控制和文件管理作为高频主任务入口。
5. 保持现有 Compose 测试入口和关键 test tag 尽量稳定，降低回归成本。

## 最终页面结构

底部导航调整为：

| Tab | 说明 | 主要职责 |
|---|---|---|
| 音频 | 高频控制页 | 查看当前设备状态、调节主音量、静音、切换输出设备 |
| 文件 | 高频管理页 | 查看文件根、浏览目录、上传、下载、重命名、移动、删除 |
| 设备 | 连接与设备管理页 | 自动发现、手动连接、当前设备、切换设备、断开/重连、连接历史 |

启动默认页规则：

| 状态 | 默认页面 |
|---|---|
| 未连接任何 Agent | 设备页 |
| 已存在可用连接 | 音频页 |

## 页面职责设计

### 音频页

音频页是连接后默认进入的主页面。它应聚焦“控制当前电脑的声音输出”。

页面结构建议：

1. 当前设备状态条
   - 显示电脑名、IP 地址、在线状态。
   - 提供“切换设备”入口，跳转到设备页。
2. 主音量卡片
   - 大号百分比显示。
   - Slider 调节音量。
   - 静音切换。
3. 输出设备列表
   - 当前输出设备明确标识。
   - 点击设备即切换。
   - 刷新操作放在顶部栏 action 或列表区域辅助操作中。

保留底部 Tab 进入文件页，不再强调音频页内部跳文件页的入口，避免重复导航路径。

### 文件页

文件页是连接后的第二个高频任务页。它应聚焦“管理当前电脑暴露的文件根”。

页面结构建议：

1. 当前设备状态条
   - 与音频页保持一致。
   - 明确提示文件操作作用于哪台电脑。
2. 文件根选择区
   - 横向卡片或底部 Sheet 选择文件根。
   - 当前根清晰高亮。
3. 面包屑路径
   - 展示当前目录层级。
   - 支持快速返回上级路径。
4. 文件列表
   - 文件夹和文件视觉区分。
   - 长按打开操作 Sheet。
5. 上传 FAB
   - 仅在当前根可写时显示。

文件页必须始终明确“当前设备”和“当前文件根”，避免用户在多台电脑环境中误删或误传文件。

### 设备页

设备页由原“连接页”升级而来，职责从“建立连接”扩展为“管理可控设备”。

页面结构建议：

1. 当前设备卡片
   - 已连接时显示电脑名、IP、版本、在线状态。
   - 操作：断开、重连、切换。
   - 未连接时显示引导文案。
2. 自动发现
   - 展示局域网扫描结果。
   - 支持重新扫描。
   - 点击发现项后执行连接/验证。
3. 手动连接
   - 输入 IP:Port。
   - 支持测试连接。
   - 成功后进入当前设备卡片，并默认跳转到音频页。
4. 最近设备
   - 保存最近成功连接的设备。
   - 支持一键重连。

“设备”作为一级 Tab 的合理性在于它不是一次性连接动作，而是长期存在的设备上下文管理入口。

## 全局布局与组件规范

### 顶部栏

顶部栏使用统一组件承载应用身份：

- 标题：Arcade Assistant
- 左侧或标题内品牌图标：SettingsRemote
- 右侧 action：按页面提供，例如刷新、文件根选择、设备状态入口
- 顶部栏不重复消费系统状态栏 inset，避免顶部空白过大

顶部栏不应承载页面标题。页面标题与任务说明应放在页面内容区，例如“输出设备”“存储位置”“当前设备”。

### 当前设备状态条

音频页和文件页必须使用一致的当前设备状态条：

```text
已连接  电脑名 · 192.168.x.x    [切换]
```

状态条职责：

- 告知当前操作目标。
- 提供切换设备入口。
- 在离线或连接异常时展示恢复操作。

### 内容间距

页面内容遵循 Material 3 的清晰层级：

- 页面左右 gutter：16dp。
- 卡片间距：16dp。
- 卡片内部 padding：16dp。
- Scaffold 的 `innerPadding` 只用于避开顶部栏和底部导航，不再叠加额外 inset 处理。

### 空状态

未连接时音频页和文件页仍保留入口，但展示统一空状态：

- 标题：尚未连接 Agent
- 描述：先连接一台电脑后即可使用音频/文件功能
- 主按钮：前往设备

该设计保留功能可发现性，同时避免用户迷失。

## 操作流程

### 首次使用

1. App 启动进入设备页。
2. 自动扫描局域网 Agent。
3. 用户选择发现的设备，或手动输入地址。
4. 连接成功后保存当前设备。
5. 自动跳转到音频页。

### 日常使用

1. App 启动检查是否有当前设备。
2. 若连接仍可用，默认进入音频页。
3. 用户通过底部 Tab 在音频和文件之间切换。
4. 需要切换电脑时，从任一主任务页的当前设备状态条进入设备页。

### 连接失效

1. 音频页和文件页展示当前设备离线状态。
2. 用户可点击“重连”。
3. 重连失败时进入设备页重新选择设备。

## 连接状态模型

当前实现中，导航层主要通过 `connectionHandle != null` 判断是否可进入音频页和文件页，而业务层还会通过 WebSocket 或 HTTP 请求感知实时连接状态。后续 UI 调整必须将连接状态提升为 App 级单一真相，避免出现“页面仍可操作但实际已断线”的状态裂缝。

建议连接状态枚举：

| 状态 | UI 表现 | 可执行操作 |
|---|---|---|
| `Disconnected` | 音频/文件显示未连接空状态，设备页显示连接入口 | 扫描、手动连接、选择最近设备 |
| `Connecting` | 设备页显示连接中，主任务页避免展示可变更操作 | 取消连接 |
| `Connected` | 音频/文件完整可用，状态条显示当前设备 | 音频控制、文件管理、切换设备 |
| `Reconnecting` | 保留当前设备上下文，状态条显示重连中，危险操作禁用 | 重试、切换设备 |
| `Offline` | 说明当前设备不可达，主任务页展示恢复入口 | 重连、切换设备 |

该状态应由全局连接管理层提供，音频页、文件页和设备页只消费同一个状态源。

## 后续扩展原则

当前方案保留底部三 Tab，是因为 Android 端目前只有三个主区域，符合 Material Design 对 3 到 5 个顶级目的地的建议。若后续增加设置、帮助、历史记录、收藏等低频页面，不应继续增加底部 Tab。

扩展原则：

1. 音频和文件保持底部主任务入口。
2. 设备在当前阶段保留为 Tab；如果用户连接后很少返回设备页，可将设备连接能力迁移为顶部状态条触发的全屏弹层或底部 Sheet。
3. 设置、帮助、关于等低频入口进入顶部菜单或设备页内部，不进入底部导航。
4. 底部导航超过 4 个目的地前必须重新评估信息架构。

真机验证：

2. 自动发现 Agent 后连接成功，自动进入音频页。
3. 音频页显示当前设备状态并可调节音量。
4. 文件页显示当前设备状态并可选择文件根。

## 风险与约束

1. 当前 `ServiceLocator.connectionHandle` 只保存内存态连接，若要实现“已连接默认进入音频页”和“最近设备”，需要补充持久化策略。
2. 重命名 `Connection` 到 `Device` 会影响测试、路由和文案，需要保持迁移范围可控。
3. 文件页操作具有破坏性，当前设备状态条必须明确，避免多设备环境误操作。
4. 不应一次性引入复杂的自适应导航组件；当前手机端优先保持 Material 3 `NavigationBar`。
5. Audio 页的“实时同步”状态不能用刷新中/非刷新中替代，应来自全局连接状态或 WebSocket 状态。
